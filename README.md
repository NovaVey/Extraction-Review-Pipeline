# Extraction-Review-Pipeline
[![CI](https://github.com/NovaVey/Extraction-Review-Pipeline/actions/workflows/ci.yml/badge.svg)](https://github.com/NovaVey/Extraction-Review-Pipeline/actions/workflows/ci.yml)

**[Live demo →](https://live-demo-erp-production.up.railway.app)** — seeded with realistic fake invoices, no signup required. State resets automatically every 10 minutes.

Document extraction with a confidence score you can act on: per-field evidence scoring instead of model self-report, a keyboard-fast review queue for anything uncertain, full correction audit trail, and a gold-set eval harness that reports auto-accept precision. TypeScript, Fastify, Postgres.

## Development

Requires Node >=22.13 and a Postgres database (see `.env.example` for the full list — `DATABASE_URL`, Supabase Storage credentials, `ANTHROPIC_API_KEY`, and a few tunables).

```bash
npm install             # installs both workspaces (api, web)
cp .env.example .env    # then fill in DATABASE_URL / SUPABASE_* / ANTHROPIC_API_KEY
npm run dev:api         # Fastify API, http://localhost:3000
npm run dev:web         # Vite dev server, proxies /api to dev:api
npm test                # api + web test suites (no real infra needed — see below)
npm run typecheck       # both workspaces + scripts/
npm run build           # both workspaces
```

Every test file stubs `DATABASE_URL`/`SUPABASE_*`/`ANTHROPIC_API_KEY` with fake local values (or mocks the network calls entirely, for `/web`) before importing app code, so `npm test` runs fully offline — no database, Storage bucket, or Anthropic API key required.

## Synthetic data

Every document under `/samples` is synthetic — generated by `scripts/make-synthetic-docs.ts` (`npm run gen:samples`). Vendor names, amounts, dates, and line items are all fabricated for testing; none of it is real personal or business data. `samples/manifest.json` records the ground-truth field values used to generate each document.

## Populating a database and running the eval harness

Once `.env` points at a real database and Storage bucket, in order:

```bash
npx tsx scripts/seed-schemas.ts             # one extraction_schemas row per doc type
npx tsx scripts/ingest-corpus.ts            # ingests all 60 synthetic docs (idempotent)
npx tsx scripts/extract-devset.ts           # extracts the 10-doc dev subset (real Anthropic API calls)
npx tsx scripts/run-eval.ts                 # compares against samples/manifest.json's ground truth
```

`extract-devset.ts` re-extracts its subset on every run — cheap, since it's only 10 documents. To extract the rest of the corpus (real API cost, ~6x more documents) use `npx tsx scripts/extract-remaining-corpus.ts` instead, which skips anything already successfully extracted so a partial/failed run only pays for what's still missing; `npx tsx scripts/extract-one.ts <documentId>` extracts a single document outside the dev subset.

`run-eval.ts` prints **auto-accept precision** — of the fields the system decided *not* to send to a human, how many were actually right — plus automation rate and overall accuracy, broken down by document type and difficulty group, and writes the full per-field detail to `eval-results.json`.
